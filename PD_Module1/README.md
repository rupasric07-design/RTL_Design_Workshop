## Introduction to Physical Design

**Physical Design (PD)** is the process of converting a synthesized RTL/netlist design into a physical layout that can eventually be manufactured as a chip.

The general RTL-to-GDSII flow can be represented as:

```text
RTL
 ↓
Synthesis
 ↓
Gate-Level Netlist
 ↓
Floorplanning
 ↓
Placement
 ↓
Clock Tree Synthesis
 ↓
Routing
 ↓
Physical Verification
 ↓
GDSII
```

In this module, I started exploring this flow using **OpenLane** and the **SKY130 open-source PDK**.

OpenLane provides an automated RTL-to-GDSII flow by integrating multiple open-source EDA tools.

## Docker Setup

Docker was used to provide a controlled environment for running the OpenLane flow.

The Docker package repository was configured and Docker components were installed.

The installation involved commands such as:

```bash
sudo apt update

sudo apt install apt-transport-https ca-certificates curl software-properties-common

curl -fsSL https://download.docker.com/linux/ubuntu/gpg | \
sudo gpg --dearmor -o /usr/share/keyrings/docker-archive-keyring.gpg
```

Docker packages were then installed using:

```bash
sudo apt install docker-ce docker-ce-cli containerd.io
```

The current user was added to the Docker group:

```bash
sudo usermod -aG docker $USER
```

The Docker group was refreshed using:

```bash
newgrp docker
```

Docker functionality was verified using:

```bash
docker
docker run hello-world
```

The `hello-world` container was used to confirm that Docker was installed and functioning correctly.

## OpenSTA / STA

I also explored the **OpenSTA (Static Timing Analysis)** environment.

OpenSTA is important for checking:

- Timing paths
- Propagation delays
- Setup requirements
- Hold requirements
- Timing constraints

## Running OpenLane

After preparing the environment, I explored the Docker-based OpenLane execution flow.

The OpenLane Docker image was used to start the OpenLane environment.

A command used during the setup was:

```bash
docker run -it -v $(pwd):/openLANE_flow \
-v $PDK_ROOT:$PDK_ROOT \
-e PDK_ROOT=$PDK_ROOT \
-u $(id -u $USER):$(id -g $USER) \
openlane:rc2
```

The command mounts the OpenLane working directory and PDK directory into the Docker container.

The user ID and group ID are also passed to the container so that generated files have the correct ownership.

The OpenLane container can also be started using:

```bash
docker run -it --entrypoint /bin/bash \
-v $(pwd):/openLANE_flow \
-v $PDK_ROOT:$PDK_ROOT \
-e PDK_ROOT=$PDK_ROOT \
-u $(id -u $USER):$(id -g $USER) \
openlane:rc2
```

This provides access to the container shell and allows the OpenLane environment to be explored interactively.

The OpenLane Docker image was also checked using:

```bash
docker images | grep rc2
```
